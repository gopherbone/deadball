# DEADBALL images & fonts

GENERATED by `tools/assets/build.py` (assets agent) -- don't hand-edit files in `images/` or `fonts/`;
change the pipeline in `tools/assets/` and re-run it. Sources are in `tools/assets/readme/*.md`.

Conventions
- Paths below are relative to `playdate/source/`; load without the `.png` extension, e.g.
  `gfx.image.new("images/ui/icons/mail")`.
- Everything is 1-bit. Opaque images are black/white PNGs. Sprites/icons that need transparency are
  grayscale+alpha PNGs (alpha 0 = transparent) -- draw them with the normal draw mode.
- **Imagetables** are matrix tables named `<name>-table-<w>-<h>.png`; load as
  `gfx.imagetable.new("images/.../<name>")`. Frames are numbered row-major (left->right, top->bottom)
  and `getImage(n)` is **1-based**. Frame orders are listed per table below.
- Total size of `images/` (excluding `images/archive/`, which the archive agent documents): 2.3 MB.

### Multi-view puppets (packed `views_<n>` chunks)

The runtime draws players from 8 camera directions so every BallCast camera sees the correct side.
All runtime puppet art is packed into a few chunk imagetables, `images/puppets/1x/views_<n>` (28x44)
and `images/puppets/2x/views_<n>` (56x88): the per-file load cost dominates on device, so there are 6 (1x) +
11 (2x) files, each sized to load in one ~40 ms loader slice.

Cells run in rows of F frames, in this order (puppets.lua rebuilds the same layout from the same constants
and checks each chunk's length; tools/assets/humanoid/sprites.py `pack_views` writes it):

1. for each view set — `pitcher_seq` (F 6), `batter_seq` (6), `catcher` (3), `umpire` (3, no away),
   `fielder` (6), `runner` (7), `runner_seq` (4), `catcher_reach` (14, views 0/2/4/6), `walker` (6) — for
   home then `_away`, views v0..v7 (2x: only `pitcher_seq`, `batter_seq`, `catcher`, `umpire`, `fielder`,
   `catcher_reach`, `walker`);
2. then the single-view rows `accent`, `accent_away`, `fan` (4 frames), `mascot`, `streaker` (2);
3. a new chunk starts when the next row would pass 96 (1x) / 40 (2x) cells; the last grid row is padded.

View v<k> = camera at azimuth k·45° around the figure (0 = in front, 90 = on its **left**, 180 = behind,
270 = on its right), 6° elevation; right-handed figures, mirror for lefties. The legacy tables map onto the
sets with the same frame numbers: `pitcher_back`/`pitcher_side` → `pitcher_seq` frames {1, 2, 5};
`batter` → `batter_seq` {1, 4, 6}; `*_seq`, `catcher`, `umpire`, `fielder`, `runner` 1:1.

Runtime (`ballcast/puppets.lua`): `P.orient` picks the view from the camera and the puppet's world facing
(callers pass `face` to `R:puppet`/`R:puppetT`), switching only 8° past the half-step (per-puppet
hysteresis). `P.preload` (from `Render.newLive`, sliced, ≈30 ms per loader slice) decodes all chunks + the
1x raccoon once per session (≈0.74 MB decoded; kept across replays, `P.dropChunks()` frees them); any later
table load prints `[bcload] late-load <path>`. Far cameras (eye above 250 ft: the blimp) draw puppets as
2x2 dots and skip nametags. The single-view legacy tables above still ship for compatibility but the
runtime reads only the chunks (and `raccoon`).

Away-team variants: `<name>_away` (pitcher_back_away, pitcher_side_away, batter_away, catcher_away, fielder_away,
runner_away, and every extra table) — same frames, gray (50% checker) jerseys. Umpire is always dark.

Facing: side-on tables face **right**; draw with `gfx.kFlippedX` to face left. The batter table is a
right-handed batter as seen from the CF camera; flip it for left-handed batters (and on reverse angles).

Sizing: the figure is 40 px tall (head top y=2 to feet y=42) at 1x and represents ~6.2 ft. See parks.json
`sprite_rule`: h = 6.2 * scale / depth; s = h / 40; s < 1.4 -> 1x table (scaled by s unless 0.8 <= s < 1.4),
else 2x table at s / 2. Draw with the anchor (feet) on the projected ground point. Airborne/dive/slide frames
are shrunk to fit the cell (same anchor).

### Puppet animatic tracks (`images/puppets/anim_tracks.json`)

Untweened "animatic" playback: a few strong held poses per action with hard cuts, plus squash/stretch,
shake, vibrate, boil, flips and spins applied at draw time as a per-billboard transform (scaleX, scaleY,
rotation, flipX, pixel offset; nearest-neighbour, pivot on the feet anchor or the body centre). 30 fps.

```
{ "version":1, "meta": {"fps":30, "anchor_1x":[14,42], "center_1x":[14,22], "shake_decay":0.55,
                        "boil":{"every":[6,14],"len":[1,2],"px":1}, "squash":{..}, "stretch":{..}},
  "tracks": { "<action>": {"loop":bool, "boil":bool,
      "keys":[ {"t":"pitcher_side_seq","f":5,"hold":2, "sx":1.15,"sy":0.87, "rot":0, "dx":0,"dy":0,
                "flip":false, "pivot":"feet"|"center", "fx":{"shake":[deg,frames]}|{"vibrate":[px,frames]}}, ...]}}}
```

- Omitted fields default to `sx=sy=1, rot=dx=dy=0, flip=false, pivot="feet"`. `dx, dy` are 1x pixels (x2 on
  the 2x table; scale them with the puppet's draw scale). `rot` is degrees, clockwise on screen.
- A key is held for `hold` frames, no easing. `fx` starts on that key: `shake` adds
  `amp * (-1)^k * 0.55^k` degrees on effect frame k; `vibrate` adds a random (dx, dy) in [-px, px] each frame.
- `boil: true` tracks (and idle puppets in general) jitter by a random 1 px every 6–14 frames for 1–2 frames,
  seeded per puppet so crowds don't sync.
- Flip composes with the puppet's own facing flip. `pivot:"center"` rotates about (14,22) — used for spins.
- Tracks: pitch_back, pitch_side, swing, homer_batter, run (loop), slide, slide_safe, slide_out,
  slide_head_safe, slide_head_out (run → drop / head-first → slide → squash at the bag → pop-up or slump),
  fielder_throw, catch, dive,
  catcher_receive, catcher_throw, ump_strike, ump_safe, fan_cheer, mascot_wave, streaker, cartwheel, backflip,
  pratfall, celebrate, turn. Reference implementation (Python): `tools/assets/humanoid/anim_tracks.py`
  (`blit`, `play`); previews in `tools/assets/humanoid/preview/anim_*.gif` / `anim_tracks.png`.
- Runtime: `ballcast/anim.lua` samples the tracks (pure function of time + a per-puppet seed, so scrubbing
  is exact); the C billboard path applies the transform (`bc3d.bb(id, x, y, z, flip, hscale, sx, sy, rot, dx, dy, pivotPx)`).

### Walk-offs, changeovers and player looks

- `walker` view set (F 6, home + `_away`, 1x and 2x; packed after `catcher_reach`): 1-2 walk (contact L, R),
  3-4 dejected walk (head down), 5-6 dejected walk dragging the bat. Hand-keyed (`poses.walk`).
- Tracks: `walk`, `slump`, `drag` (loops on `walker`), `jog` (the run cycle with longer holds),
  `practice` (the on-deck hitter's half swing back to the stance).
- `images/puppets/landmarks.json` (`sprites.py write_landmarks`, from `render_frames.py --landmarks`): per view
  set + view (`"<set>#<v>"`), 24 chars a frame: head, nose, face code, back (number), back code, knees/ankles,
  elbows/wrists, in 1x cell px at half-pixel steps (char = 40 + 2v). The C billboard path uses them to stamp
  per-player looks (`bc3d.sprite(..., widthFactor, landmarks)`, `bc3d.bb(..., look)`; bits in bc3d.c
  `lookPass`): skin dither, facial hair, socks, sleeves, batting helmet, jersey number. Body types are a
  width factor + figure height baked into the C size caches (`ballcast/looks.lua`, `puppets.lua BODY`).

## BallCast ballparks (`images/parks/`)

Static 400x240 opaque 1-bit backgrounds, one per park per camera:
`images/parks/<parkId>-<cam>.png` — load with `gfx.image.new("images/parks/park-hcl-pitch")`.

- parkIds: park-hcl, park-sta, park-pem, park-mil, park-csr, park-ncg, park-mrl, park-elc, park-farm (`park-<abbr lowercased>` as in worldgen; `park-farm` is the
  generic "Municipal Field" used for every farm park).
- cams: `pitch`, `high_home`, `lf`, `cf`, `rf`, `bleachers`.
  - `pitch`: Broadcast CF camera behind the pitcher (slightly left of center), long lens on the plate. Puppet scale s ~1.3 (pitcher) / ~1.1 (batter): draw the 1x tables unscaled.
  - `high_home`: High behind home plate (upper deck), whole field. Use for balls in play / overview.
  - `lf`: Elevated camera in the left-field seats (30 ft behind the wall, wall+45 ft up) looking in toward the infield; field visible from ~r-75 ft in. Outfield plays, throws home.
  - `cf`: Elevated camera in the center-field seats (30 ft behind the wall, wall+45 ft up) looking in toward home; field visible from ~r-75 ft in. Outfield plays, throws home.
  - `rf`: Elevated camera in the right-field seats (30 ft behind the wall, wall+45 ft up) looking in toward the infield; field visible from ~r-75 ft in. Outfield plays, throws home.
  - `bleachers`: Close shot of the first-base-side stands from shallow foul ground (crowd incidents, raccoons, streakers).
- Rendered full-frame; the top/bottom ~16 px can be covered by HUD overlays without losing anything important
  (pitch cam keeps the plate area in the middle band).

### parks.json (`images/parks/parks.json`)

```
{ "version": 1, "coords": "...", "screen": {"w":400,"h":240}, "projection": [...], "reference_python": "...",
  "parks": { "park-hcl": { "name", "abbr", "city", "team", "fences", "walls", "altitudeFt", "foulTerritory", "turf",
      "cams": { "pitch": { "eye":[x,y,z], "target":[x,y,z], "up":[0,0,1], "fov_x_deg", "cx":200, "cy":120,
                          "scale", "near":1, "right":[..], "camup":[..], "forward":[..],
                          "sprite": {"ft":6.2, "px_at_depth_100", "rule"},
                          "tests": [{"label", "p":[x,y,z], "expect":[sx,sy,depth] | null}, ...],
                          "image": "images/parks/park-hcl-pitch" }, ... } }, ... } }
```

Field coordinates are feet: home plate at the origin, +y toward CF, +x toward the 1B side, +z up
(same as `packages/sim/src/physics.ts`, so `Flight.path` samples project directly).

Projection (pinhole; basis vectors are precomputed in the JSON, so the client needs only dot products):

```
d  = p - eye
xc = dot(d, right);  yc = dot(d, camup);  zc = dot(d, forward)
if zc < near: not visible
sx = cx + scale * xc / zc
sy = cy - scale * yc / zc
```

`sx, sy` are continuous coordinates (pixel (i,j) covers [i,i+1) x [j,j+1)); draw at `math.floor`.
`depth = zc` — sort puppets far-to-near by it. Puppet height on screen `h = 6.2 * scale / depth`
(puppet tables are 40 px from head to feet at 1x): `s = h / 40`; if `s < 1.4` draw the 28x44 table
(unscaled when 0.8 <= s < 1.4, else `drawScaled(s)`), otherwise the 56x88 table at `s / 2`. Clamp `s >= 0.5` (wide shots exaggerate players, like
the mockups). Anchor the
puppet's feet on the projected ground point (x, y, 0). Ball: project (x, y, z); shadow: project (x, y, 0).

Example (park-hcl pitch): eye [-9.0, 430.0, 64.0], target [0.6, 0.0, 3.0], fov_x 7.0°, scale 3269.9711.
Test vector: home plate (0,0,0) -> [np.float64(204.511), np.float64(142.352), np.float64(434.819)]; rubber (0,60.5,0) -> [np.float64(193.454), np.float64(219.996), np.float64(374.934)].
Every camera carries ~10 such `tests` — port the math, then assert |dx|,|dy| < 0.01.

Lua port:

```lua
local function project(c, x, y, z)
  local dx, dy, dz = x - c.eye[1], y - c.eye[2], z - c.eye[3]
  local zc = dx*c.forward[1] + dy*c.forward[2] + dz*c.forward[3]
  if zc < c.near then return nil end
  local xc = dx*c.right[1] + dy*c.right[2] + dz*c.right[3]
  local yc = dx*c.camup[1] + dy*c.camup[2] + dz*c.camup[3]
  return c.cx + c.scale * xc / zc, c.cy - c.scale * yc / zc, zc
end
```

Per-park character: Bellwood (HCL) skyline + gaslamps on the wall, double deck; Sanctuary (STA) church
steeple, dark-clad crowd; Wharf Street (PEM) 25 ft LF wall with net and harbor cranes/ship, no LF seats;
Furnace (MIL) turf + smokestacks; Stockyard (CSR) mountains, water tower, windmill; Corinth Commons (NCG)
double deck, skyline; Plymouth Yard (MRL) wooden walls, tree line; Dynamo (ELC) night game, 6 light towers,
turf, lightning-bolt scoreboard; Municipal Field (farm) small wooden park, water tower, trees.
Wall distance markers are painted from the actual `fences` values. Stands are filled with the real crowd
photos from `images/crowd/` (crowd.py; per-park style mixed/dark/light/sparse), mapped upright (u = arc length
along the stands, v = height) and error-diffused; the earlier drawn head-and-shoulders crowd is only a fallback.

## BallCast live geometry (`images/parks/parks-geo.json`, `images/parks/tex/`)

For the live C renderer. Same field frame and camera math as `parks.json` (feet; home plate origin,
+y to CF, +x to 1B side, +z up). Compact JSON, coordinates rounded to 0.1 ft.

```
{ "version":1,
  "materials":[ {"name":"grass_a","gray":0.27,"outline":false}, {"name":"light_bank","gray":0.9,"outline":false,
                 "pattern":[8 bytes]}, ... ],            # index = material id
  "textures": { "crowd_mixed": {"file":"images/parks/tex/crowd_mixed","w":64,"h":45,"wrap":true}, ... },
  "parks": { "park-hcl": {
      "sky": {"top":0.97,"horizon":0.85,"stars":false},
      "polys": [ {"m":2,"l":2,"v":[[x,y,z],...]},                       # convex, 3+ verts
                {"m":18,"l":10,"v":[[..]x4],"t":"crowd_mixed","uv":[[u,v]x4]}, ... ],
      "billboards": [ {"m":35,"c":[x,y,z],"r":12} ],                       # camera-facing discs (smoke, trees, lamps)
      "lines": [ {"a":[x,y,z],"b":[x,y,z],"c":1,"w":1} ] } } }        # c: 1 white / 0 black, w: px width
```

**Materials** (fill = `gray` 0..1 through an 8x8 Bayer ordered dither, 1 = white; if `pattern` is present use it
instead: 8 bytes = rows 0..7, bit 7 = leftmost pixel, 1 = white, anchored to screen coordinates;
`outline` = draw a 1 px black edge): `ground_far`, `grass_foul`, `grass_a`, `grass_b`, `turf`, `warning_track`, `dirt`, `mound`, `chalk`, `base`, `plate`, `rubber`, `wall`, `wall_wood`, `wall_net`, `stands_wall`, `backstop`, `dugout`, `crowd`, `stands_back`, `deck_facade`, `deck_shadow`, `ad_board`, `marker`, `scoreboard`, `scoreboard_face`, `steel`, `light_bank`, `flag_dark`, `flag_light`, `lamp`, `skyline`, `landmark`, `landmark_dark`, `ship`, `smoke`, `tree`, `mountains`, `mountains_near`, `snow`, `bolt`, `treeline`.

**Draw order.** Clear to the sky: per screen row, gray = `horizon + (top - horizon) * (1 - exp(-max(el,0)/12))`
where `el` is the ray elevation in degrees (a flat `top` fill is fine too); night parks (`stars`) are near-black.
Then polygons with `l < 10` in ascending `l`, and within a layer in file order (ground: 0 far ground,
1 foul grass, 2 fair grass, 3 mowing stripes, 4 warning track, 5 infield dirt, 6 infield grass, 7 mound/home
circle, 8 bases/plate/rubber). Then everything with `l == 10` plus the billboards, sorted far -> near by the
distance from the eye to the polygon centroid (billboard centre). Clip against the near plane (z_cam >= 1)
before projecting. Finally draw `lines` (chalk, wall-top stripe, foul poles, lamp posts) as 2D lines between
projected end points (clip to the near plane). Billboards: filled disc radius `r * scale / depth`.

**Textures.** 1-bit opaque PNGs in `images/parks/tex/` (`crowd_<style>` = the photo crowd tile `images/crowd/tex-<style>-128x64` (128x64 = 48 x 24 ft, tileable, `wrap:true`; the textures table gives the file), falling back to a drawn 64x45 tile only if the photos are missing;
`ad_<brand>` 128x16 black-on-white boards; `dist_<feet>` 24x12 white numerals; `sb_<abbr>` 96x48 scoreboard
faces). A textured polygon has `t` and `uv` with one `[u,v]` per vertex in texel units (u right, v down;
for wrapping textures take `mod w/h`). Map affinely across the projected quad (vertex 0 -> uv 0 ...);
crowd uvs are not per-quad 0..1: u = arc length along the stands, v = 640 - world height (both x 128/48 texels
per ft), so the photo crowd stays upright and continuous across segments; affine mapping across a big
stands quad shows some skew/streaking — perspective-correct (or subdividing the quad) looks better.
Untextured fallback: the material `gray` — also use it when the texture would be minified (texels per
screen pixel > ~1.5, i.e. `texels_per_ft * depth / scale > 1.5`, with texels_per_ft = |uv1-uv0| / |v1-v0|);
point-sampling a minified crowd texture just makes moire.

**Counts:** park-hcl: 297 polys / 9 billboards / 55 lines; park-sta: 253 polys / 0 billboards / 48 lines; park-pem: 230 polys / 0 billboards / 46 lines; park-mil: 196 polys / 12 billboards / 58 lines; park-csr: 285 polys / 0 billboards / 46 lines; park-ncg: 298 polys / 0 billboards / 46 lines; park-mrl: 233 polys / 14 billboards / 46 lines; park-elc: 221 polys / 0 billboards / 58 lines; park-farm: 208 polys / 14 billboards / 46 lines.

**Runtime look (bc3d / ballcast/geo.lua), replacing the textured stands:** crowd polygons are not textured
any more. They use the C "crowd heads" material (material mode 2): an 8x8 head-and-shoulders tile filled
in screen space but offset by the camera's yaw/pitch (pans carry the crowd with the stands), every 8-px
column at its own fixed height, every 11th column an aisle, idle shimmer / excited bobbing from
`bc3d.crowd(level)`, a rolling wave band and camera flashes on big moments (`bc3d.crowd(level, wave,
flash)`). Sections get different tiles (`Geo.CROWD_TILE`: sunny lower deck, shaded lower deck on the 3B side,
upper deck above 40 ft). Crowd photo textures are no longer loaded for the stands (the bleacher camera's
2D photo backdrops are unchanged). Ad boards (`tex/ad_*.png`, drawn by `tools/assets/adboards.py`: an
icon, at most 3 letters, a pattern band) are textured only within the camera's quality distance or 150 ft,
and pair up as trivision boards (`bc3d.alt`) flipping every ~4 s with a 3-frame slat transition. The
diamond gets 1 px black outlines on the boundary edges of the dirt, infield grass, mound/home circles,
bases, plate and rubber (layer 17, under the chalk), and the ground chalk lines (layer 18) a black stroke
on both sides when they're at least half a pixel wide on screen. `[bcrender] cost cam=X` at scene exit
reports the C park render time per camera.

Verification: `tools/assets/preview/geo_<park>.png` shows, per row, the static background (left) and the same
camera rendered only from parks-geo.json (right), for the pitch and high_home cameras.
